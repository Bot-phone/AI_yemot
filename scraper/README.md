# מנגנון סנכרון תיעוד ימות המשיח (Yemot Docs Scraper)

מנגנון זה סורק באופן אוטומטי ומתוזמן את פורום ימות המשיח (קטגוריה 1: `https://f2.freeivr.co.il/category/1`), ממיר את התוכן לטקסט נקי לחלוטין מזבל פורומים, ומעדכן את קובצי התיעוד בתיקיית `knowledge/` במאגר.

## תכונות עיקריות
1. **סריקה שבועית מתוזמנת ב-GitHub Actions:** רצה אוטומטית פעם בשבוע (בימי ראשון ב-03:00 UTC) וכן ניתנת להפעלה ידנית דרך לשונית Actions.
2. **זיהוי והתראה על נושאים חדשים:** במידה ונוסף נושא חדש בפורום שאינו מופיע בקובץ הסיווג, הוורקר שולח בקשת התראה ל-Google Apps Script אשר שולח מייל למנהל עם קישור ישיר לנושא.
3. **סיווג גמיש (`topics_config.json`):**
   - `action: "file"` – שמירה כקובץ עצמאי ב-`knowledge/`.
   - `action: "append"` – שרשור לנושא קיים באותו קובץ (לדוגמה: איחוד מספר נושאי הגדרות קשורים).
   - `action: "ignore"` – התעלמות מהנושא (לדוגמה: אינדקסים, נושאים שנמחקו).
   - `post_filter` – סינון פוסטים ברמת נושא (לפי מחברים, הכללת/החרגת מזהי פוסטים ספציפיים `include_pids` / `exclude_pids`, ואורך מינימלי).
4. **ניקוי תוכן מתקדם (`cleaner.py`):** מסיר תגיות HTML, עוגנים, ציטוטים של משתמשים אחרים, ברכות ("ב"ה", "בס"ד", "שלום לכולם", "בהצלחה"), וממיר בלוקי הגדרות וקוד לטקסט ברור.

## ניקוי-על של קובצי הידע (Post-processing)

לאחר הרכבת התוכן, כל קובץ ידע עובר דרך `postprocess_knowledge_text(text, filename)` שב-`cleaner.py`.
הפונקציה **אידמפוטנטית** (הרצה חוזרת מחזירה פלט זהה) ומופעלת בשני מסלולים:
בזמן הכתיבה ב-`sync_docs.py`, וכן אופליין (ללא רשת) על הקבצים הקיימים דרך `scraper/postprocess.py`.

מה היא עושה:
1. **פענוח קידוד אחוזים בקישורים** – רצפי `%D7..` בעברית בתוך יעדי קישורי Markdown מפוענחים לעברית קריאה. יעד שמכיל רווח נשאר עטוף ב-`<...>` (המוסכמה שהאפליקציה מצפה לה).
2. **עוגן אחד לכל כותרת** – עוגני הניווט הכפולים `topic-N` / `post-N` מוסרים ונשאר עוגן ה-slug בלבד; מזהים כפולים באותו קובץ מקבלים סיומת `-2`, `-3` כדי שהניווט בדפדפן יהיה דטרמיניסטי.
3. **איחוד בלוק "התוספים הניתנים להגדרה בכל מודול"** – הבלוק החוזר נשמר פעם אחת בלבד בקובץ `סדר פעולות בכניסה לשלוחה לפני המעבר למודול עצמו.txt` (תחת העוגן `#תוספים-הניתנים-להגדרה-בכל-מודול`), ובשאר הקבצים הוא מוחלף בשורת הפניה אחת. הערות ייחודיות למודול שהופיעו בתוך הבלוק **נשמרות**.
4. **הסרת עמודות ריקות לחלוטין** מטבלאות גדולות (20+ שורות), עם שורת הערה המפרטת אילו עמודות הוסרו.
5. **נרמול רשימת סוגי השלוחות** (`כל סוגי השלוחות הקיימות.txt`) לצורה אחידה הניתנת לפירסור:
   `- type=<slug> — <תיאור> ([קובץ](<link>))`, כאשר ה-slug נלקח מבלוק ה-`ini` הצמוד (מקור האמת).
6. **ניקוי רווחים** – הסרת רווחים בסופי שורות, כיווץ רצפי שורות ריקות, ואיחוד קווי הפרדה `---` עוקבים.

```bash
python scraper/postprocess.py            # ניקוי כל knowledge/ (המאגר היחיד; הדסקטופ מטמיע אותו ישירות)
python scraper/postprocess.py --dry-run  # דיווח מספרים בלבד (bytes/chars/tokens), ללא כתיבה
python scraper/postprocess.py --check    # קוד יציאה 1 אם קיים קובץ שאינו נקי (שימושי ל-CI)
```

ספירת הטוקנים משתמשת ב-`tiktoken` (`o200k_base`) אם הוא מותקן, ואחרת באומדן `chars/2.44`.

## הפעלה מקומית
```bash
pip install -r scraper/requirements.txt

# הרצת בדיקה (ללא שמירה וללא התראות)
python scraper/sync_docs.py --dry-run

# סנכרון מלא
python scraper/sync_docs.py
```

## עקרון איחוד הידע למודלי AI (Knowledge Consolidation Principle)

אחד העקרונות המרכזיים בארכיטקטורת הידע של הפרויקט הוא **איחוד נושאים חופפים ומשלימים לקובץ אב מרכזי אחד** (לדוגמה: איחוד כלל סוגי הניתובים, התורים, וההפניות לקובץ אחד, או איחוד כלל שיטות הניקוד והדירוג לקובץ אחד).

### מדוע זה קריטי?
- **מניעת בחירה שגויה של מודל השפה:** כאשר מודל AI מקבל שאילתה או בקשת אפיון שלוחה מהמשתמש, אם המידע מחולק לעשרות קבצים מפוצלים של תתי-סוגים, המודל עשוי לחשוב שמתאים סוג פלוני (למשל ניתוב פשוט) ולהמליץ עליו מיד. לעומת זאת, כאשר הוא מקבל בהקשר את כל הסוגים והחלופות יחד באותו קובץ, הוא רואה שסוג אלמוני (למשל ניתוביה מותאמת אישית, ניתוב זמנים או ניתוב טלגרם) מתאים ומדויק בהרבה למקרה המבוקש.
- **השוואה והבחנה איכותית:** ריכוז כל הווריאציות של אותו מודול מאפשר למודל להבין את הניואנסים, היתרונות והמגבלות של כל הגדרה, ולבחור את הפתרון האופטימלי ביותר.
- **עבודה לפי עיקרון זה בסיווגים עתידיים:** כאשר מזוהה נושא חדש בפורום (`topics_config.json`), יש לבחון תמיד האם הוא מהווה הרחבה, חלופה או שדרוג של מודול קיים. אם כן – יש להגדירו כ-`action: "append"` לקובץ הנושא הראשי ולא לפתוח קובץ מפוצל ונפרד.

## משתני סביבה וסודות (GitHub Secrets)
- `GAS_WEBAPP_URL`: כתובת ה-Web App של Google Apps Script לשליחת התראות.
- `ADMIN_SECRET`: סיסמת המנהל לאימות מול Apps Script (ברירת מחדל: `yemot_admin_secret`).
- `ALERT_EMAIL`: מוגדר ב-Script Properties של Apps Script כיעד לשליחת ההתראות.
